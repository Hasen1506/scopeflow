# WS-01: money core, tax math and data foundation

Covers M3, M4, M1, M2, H13, M5, M6, M25, L6 (and supports C7, LT-01, LT-07). Plan §9.2–9.3.

## Behaviour changes

**Integer money (M3, M4).** Every computation in `lib/money.ts`, `lib/gst.ts` and
`lib/agreement-totals.ts` runs on safe integers in the currency's ISO 4217 minor unit
(`lib/minor.ts`). Decimal input is parsed as text, so `1.005` rounds half-up to `1.01` (the old
`Math.round(n * 100) / 100` gave `1.00`). Signed scope content keeps its decimal numbers; no
canonical form or hash changes (`tests/golden/*` are byte-identical).

- Exponents live in `config/currencies.ts` (`exponent`): JPY 0, every other offered code 2 (ISO, so
  IDR and PKR are 2 although Intl displays them with 0). Codes that are not offered (KWD/BHD/OMR = 3,
  KRW/VND… = 0) are in `otherExponents`. All 29 offered currencies are kept.
- `formatMoney` shows exactly the exponent's decimals and rounds exactly: `¥1,800`, `₹29,500.00`.
- A yen deposit is whole yen: ¥1,000 @ 33.333% → deposit ¥333, balance ¥667; recording ¥333 covers it.
- Half-cent ties now round up. `tests/differential/ws-01-totals.test.mjs` shows these are the only
  differences from the old float totals (e.g. ₹10.05 @ 10% tax: ₹1.01 now, ₹1.00 before).
- `round2` is exported from `lib/minor.ts` as an exact shim for read paths that still keep decimal
  amounts (lib/invoice.ts, lib/invoice-status.ts, lib/statement.ts, lib/ledger.ts, insights). Their
  owners (WS-03/04/05/09) switch to minor units and delete their local `round2`.

**GST engine (M1, M2).** `gstFromExclusive(taxable, rate, supply)` and
`gstFromInclusive(amount, rate, supply)` return a `GstBreakdown` in minor units. Each head is
computed from the taxable value (CGST = SGST = round(taxable × rate/2 %), IGST = round(taxable ×
rate %)), so CGST and SGST are always equal; an inclusive amount's residue goes to an explicit
`round_off` (₹100 incl. 18% intra-state → 84.75 + 7.63 + 7.63 − 0.01). `supply` is `intra`,
`inter`, `export` (rate 0 = under LUT/bond) or `none` (one undivided "GST" head). The legacy
`gstSplit()` is unchanged in behaviour (odd paisa to SGST) so invoices issued before WS-03 rewires
`lib/invoice.ts` read back exactly as issued. Default entry for new invoices is exclusive (WS-03).

**Place of supply (H13).** `placeOfSupply({seller_state, client_gstin, client_state,
client_country, forex_confirmed})` decides by the recipient's location and never by currency
(`currency` is accepted and ignored). A client outside India (`client_country` ≠ IN, or state 96)
is a zero-rated export only with `forex_confirmed` (consideration in convertible foreign exchange,
or INR where the RBI permits); otherwise IGST applies and a warning is returned. Exports carry the
LUT/bond note. An Indian client billed in USD gets CGST + SGST or IGST by state. Result fields:
`code, basis, supply, zero_rated, warnings`. Needs CA review.

**Agreement totals (LT-01 support).** `agreementTotals(content, entries, {supply | place})`:
fee = baseline + approved change orders; heads from the GST engine on the whole current fee (the
same head logic everywhere for a project, §9.3: ₹32,500.50 → ₹38,350.59 single head / IGST,
₹38,350.60 intra-state); deposit on the signed baseline total; milestones frozen at baseline
approval, with approved COs reported as `unscheduled`. Also returns `baseline`, `change_orders`,
`supply`, `place` and `breakdown`. `coDisplay()` in `lib/money.ts` gives "+₹10,000.00 + GST
₹1,800.00 = +₹11,800.00" for CO cards (WS-03/WS-07).

**Scope validation (M5, M6, LT-07 support).** The fee, item `price`/`unit_price` and a money
revision bank (amount, overage rate) may carry at most the currency's decimals ("Use at most 2
decimals"; "Use whole amounts: JPY has no decimals"). Negative values say "can't be negative".
`fieldIssues(error)` / `fieldLabel(path)` give field-level messages (`items.0.price` → "Item 1
price") for the editor (WS-09). Optional `items[].unit_price`: when set, the line total is qty ×
unit price (`lineTotal()`), and `feeCheck` compares line totals; legacy `price` remains the line
total. `changeOrderMoneyProblems(co, currency)` is the same rule for change orders (WS-05 calls it
in `checkEntry`). Already-signed content is never re-validated.

**FX chain (L6).** `/api/fx` asks, in order: Frankfurter/ECB (`SCOPEFLOW_FX_URL`), FBIL reference
rates for INR pairs with USD, GBP, EUR, JPY, AED, IDR (via Frankfurter v2's FBIL provider,
`SCOPEFLOW_FBIL_URL`), then `SCOPEFLOW_FX_FALLBACK_URL`. The locked rate records `{rate, source,
as_of}` with the source that published it ("FBIL reference rate", "ECB reference rate", …). When
all fail the answer is 502 `fx_unavailable` with `manual: {required: ['rate','source','as_of']}`,
and the owner enters the rate with its source and date (the scope schema requires both).

**SQL adapter (M25).** `db/client.ts` rewrites `?` placeholders with a tokenizer that skips string
literals (including `E'…'`), quoted identifiers, dollar-quoted bodies and comments; `??` is a
literal `?` (JSONB key-exists) and `?|`/`?&` are kept. `isMutation()` also recognises
data-modifying CTEs (`WITH n AS (UPDATE …) INSERT …`) and locking reads, so they take the write
transaction and the scoped lock.

**Migration `0015_ws-01_money.sql`.** Adds `scopeflow.currency_exponent(code)` and two generated
columns on `invoices`: `currency_exponent` and `amount_minor` (exact, from the stored amount via
numeric). Generated columns backfill every issued invoice without an UPDATE (the immutability
trigger is untouched). Additive and idempotent.

**C7 support.** `scripts/migrate.mjs` uses `DATABASE_MIGRATION_URL` (table-owner role) when set,
else `DATABASE_URL`, so the runtime role can stop owning the tables (WS-10).

## Environment variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `SCOPEFLOW_FBIL_URL` | `https://api.frankfurter.dev/v2/rates` when `SCOPEFLOW_FX_URL` is unset; none when `SCOPEFLOW_FX_URL` points elsewhere (e.g. CI's local double) | FBIL INR reference rates (v2 shape). `off` disables this step. |
| `SCOPEFLOW_FX_FALLBACK_URL` | unset | Optional second provider (Frankfurter v1 `?base=&symbols=` or v2 array shape). |
| `DATABASE_MIGRATION_URL` | unset (uses `DATABASE_URL`) | Owner role for `npm run db:migrate` (C7, WS-10). |

`SCOPEFLOW_FX_URL=off` still turns every automatic lookup off.

## Operator steps

1. Deploy runs `npm run db:migrate` (adds the generated columns; on a large `invoices` table this
   rewrites the table once under an exclusive lock: run it in the deploy window).
2. Optionally set `SCOPEFLOW_FX_FALLBACK_URL`. No secrets are needed.
3. Nothing else changes in production config.
