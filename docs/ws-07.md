# WS-07: Client review experience & i18n

The page a client opens from a review link (`/review/<token>`): what changed, and how.

## Behaviour changes

| ID | What the client sees now |
| --- | --- |
| LT-01 | An **Agreement now** card on approved links: fee after every approved change order, each tax head (whatever `agreementTotals()` returns: one `GST` head today, CGST + SGST or IGST once WS-01's GST engine lands), total incl. tax, paid, balance. The frozen v1 scope is labelled **As first approved** (eyebrow and "Fee as first approved") once a change order changed the fee. |
| M7 / SF-23 | Change-order cards state the price **with tax** (`+₹7,500.50 + GST ₹1,350.09 = ₹8,850.59`) and the effect on the agreement total (`₹29,500.00 → ₹38,350.59`), computed by applying the change order through the same `agreementTotals()` fold. Decided change orders are listed as compact cards (approved / declined / withdrawn, by whom); a decided one has no form. |
| SF-23 | Approving shows a calm success state ("Approved. Thank you.", focus moves to it) with exactly one next step: pay the deposit (link to the deposit block), else pay the first open invoice, else "nothing else is needed". No animation. |
| H4 / H10 UI | When the review API marks a link read-only (`readonly: true`, `readonly_reason: 'revoked' \| 'rotated' \| 'account_closed'`, optional `kept_until`; `account_closed: true` also accepted), the page shows a banner ("This link is closed for new changes" / "The creator closed their Scopeflow account … kept for you until <date>"), the record, receipt, statement and invoice PDFs, and **no** decision, change-order, countersign or payment action. |
| LT-10 | Unknown, replaced, withdrawn (404) and expired (410) links show a plain page: what happened, "Ask the person who sent it for a new link", an **Ask the sender** `mailto:` (addressed to the sender when the API gives `sender: {name, email}` on 410), the home page and "Check a receipt". No Reload button (it never helped). Only a server or network failure offers **Try again**. `app/not-found.tsx` uses the same plain wording. |
| L12 UI | The typed name and comment are kept on the device (localStorage, key = first 16 characters of the token, removed once the decision is saved). A 409 on decision reloads the page, shows "A newer version of this scope exists" (with a link when the API returns `newer_url`, else "ask the sender"), and keeps the comment. Coming back to the tab (at most once a minute) re-checks for a newer version. |
| M32 | A **DataNotice** under the decision form: what is recorded (name, time, IP, browser) and for how many days (`retention_days` from the review API, served by WS-08), else the honest "kept while the creator keeps this project" line; links to `/privacy#client-data`, a new client section in the privacy notice. |
| SF-09 | English, Hindi and Tamil **chrome** (`messages/{en,hi,ta}.json`, `lib/i18n`). Language order: `?lang=` → the reader's own choice on this device → the creator's `scope.language` → `Accept-Language` → English. The server-rendered first paint already uses `?lang`/Accept-Language. A **LanguagePicker** in the client header. The scope content, amounts, ledger record lines and comments are shown exactly as written; `<main lang>` follows the language. |
| LT-13 | The client header is the brand and the language picker only: no EARLY BETA badge, no creator navigation. The site footer's "Early beta" legal line is hidden on this page (WS-09 change request below). Jargon: "fingerprint" → "record check code", "signature" → "seal", chip wording per plan §6.1 ("Verified · sealed by Scopeflow", "Record unchanged · saved before sealing was on"), plus a "Words on this page" glossary. The reviewer guide drops "EARLY BETA" and explains the words. |
| LT-15 | No input handler normalises dashes; a regression test types `a – b — c` and checks the request body, the stored comment and the rendered comment. |
| LT-19 | Mobile: the client page CSS module wraps long words, caps inputs at the container, stacks action buttons under 480 px; tests at Pixel 7, iPhone 13 and 390 px check no sideways scroll and that change-order actions are reachable by touch. |

## Slots: props used

Exactly what the client page passes today (owners' slot types are still `Record<string, unknown>`, so these are the contract WS-07 relies on):

- Implemented here:
  - `app/components/slots/language-picker.tsx`: `{value: ClientLanguage, onChange(lang), id?}` (default id `client-language`), in `client-header.tsx`.
  - `app/components/slots/data-notice.tsx`: `{lang?, retentionDays?: number | null, dataNotice?: string | null}`, under the decision form; values from the review GET (`retention_days`, `data_notice`), else from `/api/account/notice/{token}`.
- Mounted here, implemented by their owners. Each sits in `SlotOr` (`app/review/[token]/slot.tsx`), so the page keeps its own fallback until the slot renders something:
  - **PayBlock** (WS-04), `SlotOr name="pay-block"`, approved and not read-only only: `{token, purpose?: 'deposit' | 'invoice', seq? (invoice seq), onPaid}`. When it fills, the page hides its own invoice Pay buttons.
  - **CoCard** (WS-05), `SlotOr name="co-card"`, pending and decided change orders: `{co, agreement, scope (content), mode: 'client', token, otpSession, needsOtp, verified, onDecided}`. Fallback: the page's own change-order card (pending) / `DecidedChangeOrder` (decided).
  - **RetainerCounter** (WS-05), `SlotOr name="retainer-counter"`, only when `ledger.retainer` is set: `{retainer}`.
  - **OtpGate** (WS-02): `{token, to, channel, session, onVerified, purpose?}`; **Countersign** (WS-02, page component): `{token, content, version, state, timeZone, identity, otpSession, onOtpVerified, onSigned}`. Both hidden on read-only links.
  - **EvidenceBlock** (page component) renders WS-02's `evidence` (`RecordEvidence`, `app/review/[token]/evidence.tsx`).
- OpenAPI: `lib/openapi/ws-07.ts` adds schemas only (`ClientLanguage`, `ClientReviewEvidence`, `ClientReviewFields`: `evidence`, `newer_version`, `newer_url`, `link_expires_text`, `readonly`, `readonly_reason`, `account_closed`, `kept_until`, `retention_days`, `data_notice`, all optional). `tests/property/ws-00-contracts.test.mjs` now only requires fragments to be objects (marked `// changed by WS-07`).

## Change requests

- **WS-09**: a `ClientNotice` (or equivalent) way for the site footer/legal line to stay hidden on `/review/*`; WS-07 hides the "Early beta" line on this page meanwhile.
- **WS-02 / WS-04**: `ledger.online_payments` should come from `routeForOwner` (the owner's payment route), not the env-wide `paymentsStatus(...).enabled` it reads today in `app/api/review/[token]/route.ts`.
- **WS-10**: add Playwright mobile projects (Pixel 7, iPhone 13) to `playwright.config.ts`; `tests/e2e/ws-07-mobile.spec.ts` sets the devices per test until then.
- **Post-merge (WS-02)**: swap the page's local `RecordEvidence` type and owner-session line for WS-02's `RecordEvidence` / `OwnerSessionFlag`, and point `OtpGate` at WS-02's final target/endpoint.
- **WS-08**: serve `/api/account/notice/{token}` (`{retention_days?, data_notice?}`); the page calls it and falls back to the honest default line on any error.

## Env vars, accounts, migrations

None. No migration (language preference stays on the reader's device; the creator's choice is the existing optional `scope.language`).

## Operator steps

None. After deploy, open a review link with `?lang=ta` and `?lang=hi`, and an unknown `/review/<64 hex>` link, as a smoke check.
