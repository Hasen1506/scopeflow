# WS-10: platform security, ops, OAuth/MCP, CI and analytics

What changed, why, the new environment variables and what an operator has to do. Items refer to the
coverage matrix (`tests/coverage-matrix.json`, IMPLEMENTATION_PLAN.md §14).

## Behaviour changes

| Item | Before | Now |
| --- | --- | --- |
| **H3** client IP | The left-most `X-Forwarded-For` entry (chosen by the caller), so rotating it bypassed every per-IP limit (live test: 330 × 200). | `lib/origin.ts clientIpFrom()`: with `SCOPEFLOW_TRUSTED_HOPS=n` the n-th entry from the right (Render appends one: `1`); with `SCOPEFLOW_TRUSTED_PROXY=cloudflare`, `cf-connecting-ip` when the request has a `cf-ray` **and** the peer Render saw is a Cloudflare edge address (published ranges, override `SCOPEFLOW_CLOUDFLARE_IPS`). Unconfigured: headers ignored (`unknown`). IPv6 is keyed by /64. |
| **M26** reads | Every read limit was a database upsert. | `allowRead()` is an in-memory sliding one-minute window per instance (`lib/rate-memory.ts`); writes keep the database counter. Bound the total with Cloudflare rules (below). Redaction on `GET /api/scopes` is WS-08's to remove; with nothing to redact it writes no rows. |
| **M27** sessions | Neon was asked on every request, several times per request. | `getUser()` is memoised per request (keyed by Next's request headers object). `ownerAuth()` lets GET/HEAD use Neon Auth's signed session cookie cache (60 s); every state-changing request and every direct `getUser()` call still verifies with Neon (`disableCookieCache`). |
| **M28** errors | Anything unexpected was a 503 "try again". | `lib/errors.ts errorResponse()` (used by `failure()`): typed errors keep their status (400 with `fields`, 403, 409, 429 + `Retry-After`, 503 only for `Unavailable`/a dependency that is down); unique-key races 409 `conflict`; Scopeflow immutability guards 409 `immutable`; database connection failures 503 `unavailable` `dependency: database`; everything else **500 with `error_id`** (also logged with the stack). `lib/idempotency.ts withIdempotency()` makes a write replay its stored reply for a repeated `Idempotency-Key` (24 h). The MCP money tools use it; the decision route adopts it in WS-02. `validationFromZod()` turns zod issues into labelled field messages (LT-06). |
| **C7** roles | The app ran as the table owner, so any SQL injection or bug could `DISABLE TRIGGER`, and `set_config('scopeflow.allow_delete','on')` bypassed immutability for anyone. | Migration `0016` creates group role `scopeflow_app` (no ownership, no TRUNCATE/TRIGGER/REFERENCES, no DELETE on the ledger) and redefines `scopeflow.deletion_allowed()` so the bypass works only for the table owner, i.e. inside SECURITY DEFINER functions. `scopeflow.delete_project_tombstone(project, owner, actor)` deletes a project only when it has no decided version, no ledger entry and no legal hold, and writes `deletion_audit` (append-only) for every outcome. |
| **C7** timestamps | RFC 3161 only when someone set `SCOPEFLOW_TSA_URL`. | `render.yaml` sets `SCOPEFLOW_TSA_URL=https://freetsa.org/tsr` by default (decision anchors and cosignatures are stamped by WS-02's code), and the daily **signed head digest** is stamped too: `GET /api/heads/<YYYY-MM-DD>` lists every ledger head at the end of that UTC date (project keyed by a hash), the SHA-256 digest of the sorted lines `"<p> <seq> <hash>"`, an Ed25519 signature over `scopeflow-heads-v1:<date>:<digest>` and the RFC 3161 token. Published once by the cron job; stored rows are immutable. Clients pin their line (`?project=<id>`) and the digest. |
| **H15/OP-02** deploy | Free plan, migrations at every boot, one cron chain. | Web service on **Starter**, `preDeployCommand: npm run db:migrate:deploy` (owner role via `DATABASE_MIGRATION_URL`), `startCommand: npm start`. |
| **M31/OP-03** crons | One `&&` chain: a failing reminders step skipped reconciliation. | Four cron services, each `node scripts/cron.mjs <job...>`; every job runs in its own process and is recorded in `cron_runs`; `/api/readiness` shows last run, staleness and failures. Jobs: `retention` (+ `heads`, `housekeeping`), `reminders`, `reconcile` (every 6 h, no mail dependency), `check-models` (+ `analytics`). |
| **H16/OP-01** host | `APP_URL` hard-coded to the onrender host; MCP resource mismatch. | `APP_URL` is `sync: false` (set `https://scope-flow.tech` in the dashboard). `proxy.ts`: any other public host gets **308** to the same path on `APP_URL` for pages and `.well-known` documents, **421** with `canonical_url` for `/api/*`, `/mcp` and the OAuth token/register/revoke endpoints. Health/readiness, webhooks (`/api/payments/*`, `/api/inbound/*`, `/api/whatsapp/*`, `/api/mail/events/*`), `/api/heads/*`, internal names and IP literals are never redirected. Well-known metadata always derives from `APP_URL`. |
| **L10** build | `experimental.cpus: 2` hard-coded; dev dependencies in the runtime image. | `NEXT_BUILD_CPUS` (optional) instead; `npm run build:capped` (`--max-old-space-size=460`) in CI and on Render; Render prunes dev dependencies after the build. |
| **M30** health | `/api/health` 200 even with signing off. | `/api/health`: DB reachable and, in production, signing `dedicated` → 200, else 503 (`reason`). `/api/readiness` (operator token) reports everything else (`summary.<check> = ok|warn|off|fail`). |
| **M22** consent | Headline used the self-chosen client name. | Headline names the redirect host; DCR clients show "Unverified · from <host>", Client ID Metadata Document clients "Verified domain". DCR names containing ChatGPT, OpenAI, Claude, Anthropic or Scopeflow are refused (`400 reserved_name`) unless every redirect URI is on that brand's domain and the domain is verified (`OAUTH_VERIFIED_DOMAINS`, default `chatgpt.com,openai.com,claude.ai,claude.com,anthropic.com`, plus `OAUTH_CIMD_HOSTS`). |
| **M23** tokens | The code was deleted before the client was checked; replay, refresh reuse and refresh revocation left tokens alive. | Token families (`oauth_grants`, one per consent). A code presented by another client: 401 `invalid_client`, code untouched. A replayed code revokes everything it issued. Refresh tokens rotate; presenting a rotated one revokes the family. Revoking a refresh token revokes its access tokens. |
| **M24** connected apps | One coarse "disconnect all". | `/connect` lists one entry per grant: name, verified/unverified domain, scopes, connected, last used; per-grant **Disconnect** (`DELETE /api/oauth/grants?grant=<id>`), plus "Disconnect all". |
| **SF-14** analytics | None. | Database triggers record `link_opened`, `decision`, `co_proposed`, `co_approved`, `payment_marked`, `invoice_issued` in `analytics_events` with ids and numbers only (no email, phone, name, IP, user agent or free text). Owners opt out (`PATCH /api/analytics {opt_out}`; deletes their events); the operator sees funnel counts at `GET /api/analytics` with the admin token; optional PostHog EU export (hashed ids). |
| **SF-26** MCP | — | New tools: `list_rate_card`, `propose_retainer_usage`, `list_invoices`, `issue_invoice` (user-confirmed), `record_payment_received`. Each goes through the owner route, so its rules (invoice cap C2, baseline checks) apply; writes are idempotent by `request_id`; identity fields are stripped. OAuth scopes are unchanged. `list_rate_card` reads WS-05's `rate_cards` once it exists (empty until then); `propose_retainer_usage` records once WS-05 enables the `usage` ledger kind (until then it answers `retainer_unavailable`). |
| **L14** CI gate | Report-only. | `scripts/check-coverage.mjs` is blocking in CI: unknown tags fail, and every matrix item of a **landed** workstream (its `docs/ws-XX.md` exists) needs a `@covers <ID>` test. `--strict` (or `COVERAGE_STRICT=1`) requires every item, for the final integration. Provider contract fixtures: `tests/fixtures/providers/`. CI runs the Pixel 7 / iPhone 13 Playwright projects for `*mobile*.spec.ts`. |

## New environment variables

| Variable | Where | Purpose |
| --- | --- | --- |
| `DATABASE_MIGRATION_URL` | web (preDeploy) | Owner role connection, migrations only. |
| `SCOPEFLOW_TRUSTED_PROXY` | web | `cloudflare` when Cloudflare is in front (render.yaml sets it). |
| `SCOPEFLOW_TRUSTED_HOPS` | web, CI | Proxies that append to X-Forwarded-For (`1` on Render; default 1 when `RENDER` is set, else 0). |
| `SCOPEFLOW_CLOUDFLARE_IPS` | web (optional) | Override the Cloudflare ranges (comma-separated CIDRs). |
| `SCOPEFLOW_ADMIN_TOKEN` | web + crons | Operator token for `/api/readiness`, `/api/analytics`, the cron callbacks (falls back to `SCOPEFLOW_CRON_SECRET`). |
| `SCOPEFLOW_ENCRYPTION_KEY` / `_PREVIOUS` | web | 32-byte base64 KEK for `lib/crypto-box.ts` (BYO payment keys, WS-04). |
| `SCOPEFLOW_ANALYTICS` | web | `on` (default) / `off` (no counts, no export). |
| `POSTHOG_KEY`, `POSTHOG_HOST` | web + check-models cron | Optional PostHog export (default host `https://eu.i.posthog.com`). `SCOPEFLOW_ANALYTICS_SALT` optional. |
| `OAUTH_VERIFIED_DOMAINS` | web (optional) | Domains whose redirect URIs may use a reserved client name. |
| `NEXT_BUILD_CPUS` | build (optional) | Static-generation workers. |
| `SCOPEFLOW_FBIL_URL` | CI | Set by WS-10 for WS-01: `http://127.0.0.1:55434/fbil`, the local FBIL double (Frankfurter v2 shape) in `tests/support/tsa-service.mjs`. Production keeps WS-01's default (or `off`). |

## Operator steps (in order)

1. **Render plan.** Move the web service and the cron jobs to Starter (cost in DEPLOY.md).
2. **Roles (C7).** The deploy that contains migration `0016` creates `scopeflow_app` if the migration role has CREATEROLE (Neon's owner role does). Then create the runtime login role once, as the owner:
   ```sql
   CREATE ROLE scopeflow_runtime LOGIN PASSWORD '<generated>' IN ROLE scopeflow_app;
   ```
   Set `DATABASE_MIGRATION_URL` to the current owner connection string and, **after WS-08 has moved account deletion and draft expiry onto `scopeflow.delete_project_tombstone` / its own SECURITY DEFINER functions**, set `DATABASE_URL` (web and crons) to `scopeflow_runtime`. Until then keep `DATABASE_URL` on the owner role: with the app role, the old `set_config` bypass in account deletion and draft expiry is refused by design. `/api/readiness` → `db_role` shows `warn` while the runtime role owns the tables.
3. **APP_URL** = `https://scope-flow.tech` in the dashboard; check that `https://scopeflow-qnng.onrender.com/review/x` answers 308 and `/.well-known/oauth-protected-resource` shows `resource: https://scope-flow.tech/mcp`. Point webhooks at the canonical host too (they still work on the onrender host).
4. **Cloudflare rate limiting rules** (the in-memory read limit is per instance): `/api/review/*` 300 requests/min per IP, `/oauth/register` 20/min, `/oauth/token` 60/min, `/api/whatsapp/webhook` and `/api/inbound/*` 60/min, `/api/verify` 60/min. Keep `SCOPEFLOW_TRUSTED_PROXY=cloudflare` only while Cloudflare proxies the domain.
5. **TSA.** The default `https://freetsa.org/tsr` is free and best effort; set a commercial TSA for SLAs. `/api/readiness` → `tsa`, `heads`.
6. **Analytics.** To stop collection for the whole server (not only exports): `ALTER ROLE scopeflow_runtime SET scopeflow.analytics = 'off';`.
7. After deploy: `/api/health` 200; `curl -H "Authorization: Bearer $SCOPEFLOW_ADMIN_TOKEN" https://scope-flow.tech/api/readiness` shows no `fail`; run each cron service once by hand and check `checks.cron.jobs`.

## Cold-start probe (H15, not in CI)

On Starter there is no spin-down; to confirm after a plan change:

```sh
for i in 1 2 3; do curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' https://scope-flow.tech/api/health; sleep 900; done
```

Every line should be `200` well under a second; a multi-second first response after 15 idle minutes means the service is still on a plan that sleeps.

## For other workstreams

- `lib/errors.ts`: throw `ValidationError(fields)`, `Conflict(code)`, `RateLimited(s)`, `Unavailable(dep)`, `Forbidden(code)`; `failure(e)` turns them (and everything else) into the right reply. `validationFromZod(issues, labels)` for field messages.
- `lib/idempotency.ts`: `withIdempotency(request, scope, body, () => handler())`.
- `lib/crypto-box.ts`: `seal(secret, aad)`, `open(box, aad)`, `rewrap(box, aad)`; bind `aad` to the row and column.
- `lib/readiness.ts`: add a check to `READINESS_CHECKS` by change request (cheap, no secrets, never throws).
- `lib/analytics.ts`: events are recorded by triggers; to add an event, add it to the `analytics_events.event` CHECK list and a trigger in your migration.
- `scopeflow.delete_project_tombstone(project, owner, actor)` returns `deleted | refused_decided | refused_ledger | refused_legal_hold | not_found`.
- Tests: read limits are in memory, so `tests/run-local.mjs` clears them between suites through `DELETE /api/readiness?scope=read-limits` (operator token, test servers on localhost only). Live suites that hammer one read endpoint should vary their key or stay under the limit.
- Coverage: tag tests `// @covers <ID>`; add `docs/ws-XX.md` in your PR, which turns the gate on for your items.
