## Part A (this PR so far)

### L8: workspace split (no behaviour change)

`app/workspace.tsx` (85 KB, one component) is now `app/workspace/**`:

| File | What moved there |
|---|---|
| `shell.tsx` | `Workspace` (default export): header, landing, tabs, project head, preview column, dialogs |
| `state.tsx` | `useWorkspace()`: every piece of state, effect and action of the old component, verbatim, plus shared types/constants (`OvProject`, `Overview`, `moneyMap`, `EMAIL`, `STALE_DAYS`, `Tpl`) |
| `project-list.tsx` | Projects home tab (`projectList`) and `UnsavedCard` |
| `editor.tsx` | Editor fields and step 1 "Scope" (`editorFields`, `scopeStep`) |
| `approval.tsx` | Step 2 "Approval" (`approvalStep`) |
| `changes.tsx` | Step 3 "Changes" (`changesStep`) |
| `money.tsx` | Step 4 "Payment & receipts" (`paymentStep`) with `PaymentPanel`, `PaymentForm`, `RefundForm`, `ReceiptList` |
| `settings.tsx` | Project settings (`settingsStep`) |

How it stays identical: the code was moved by line range with a script; the only generated text is the
hook wrapper/return, the `const {...}=w` destructuring and imports. The section modules are plain render
functions called inline (`{approvalStep(w)}`), not new components, so the React tree, hook order and
DOM are exactly as before; `tests/e2e/golden-flow.spec.ts` and its `__golden__` set are unchanged.
`app/page.tsx` imports `./workspace/shell`.

Test: `tests/ws-09-bundle.test.mjs` (`@covers L8`, run by `test:local` after the build): each workspace
module < 48 KB; the JS the workspace route loads stays under `WS09_ROUTE_JS_BUDGET` (default 2,500,000 raw bytes;
the measured size is printed in CI).

### LT-05: approval status refreshes without a reload

While the open version is pending (link not revoked, project not archived) the workspace re-reads
`GET /api/scopes/:id` every 15 s, on window focus and when the tab becomes visible (only while visible).
When the version is decided, the open project, history, co-signs, project list and overview update.
No new endpoint. Test: `tests/e2e/ws-09-workspace.spec.ts` (`@covers LT-05`).

### LT-06: field-level validation

`lib/editor.ts` `fieldErrors` / `humanIssue` / `validationBanner` turn schema issues (and a server
`{fields:{...}}` answer, WS-10 errors) into messages under Project name, Client, Deliverables and Project fee,
e.g. `Use at least 3 characters`. The banner names fields by label ("Check the highlighted fields: Project name,
Client, Deliverables."); editing a field clears its message and the banner. Tests: `tests/property/ws-09-editor.test.mjs`
(unit + property), e2e above.

### LT-07: number inputs are explained, never coerced

Item prices and the project fee keep what was typed. Negative → "Price can't be negative" / "The fee can't be
negative" (the existing fee message from `numberProblems` still wins); above the schema cap (10,000,000) →
"Max ₹1,00,00,000" in the scope's currency (`maxAmountLabel`). Save is still refused by the schema, now with field messages.

### LT-12: plurals

`lib/plural.ts` (`Intl.PluralRules`): `plural('concept',1)` → `1 concept`; the scope paper shows `× 1 concept`
instead of `×1 concepts`. Casing pass on editor/landing is not done yet (no concrete inconsistency located in part A).
