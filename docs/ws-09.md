### L8: workspace split (no behaviour change)

`app/workspace.tsx` (85 KB, one component) is now `app/workspace/**`:

| File | What moved there |

DOM are exactly as before; `tests/e2e/golden-flow.spec.ts` and its `__golden__` set are unchanged.
`app/page.tsx` imports `./workspace/shell`.

Test: `tests/ws-09-bundle.test.mjs` (`@covers L8`, run by `test:local` after the build): each workspace
module < 48 KB; the JS the workspace route loads stays under `WS09_ROUTE_JS_BUDGET` (default 2,500,000 raw bytes;
the measured size is printed in CI).

### LT-05: approval status refreshes without a reload

While the open version is pending (link not revoked, project not archived) the workspace re-reads
`GET /api/scopes/:id` every 15 s, on window focus and when the tab becomes visible (only while visible).
When the version is decided, the open project, history, co-signs, project list and overview update.
No new endpoint. Test: `tests/e2e/ws-09-workspace.spec.ts` (`@covers LT-05`).

### SF-16: Insights made full (₹ recovered as hero)

Every earlier card, observation and the by-client list is kept as it was (`computeInsights(rows)` without the
new facts returns the same earlier figures; pinned by a test). Added (`lib/insights.ts`, `app/api/insights/route.ts`,
`app/insights-panel.tsx`):

- **Route folds every approved baseline** (C4 family). Each approved version is folded with its own entries and
  `mergeBaselines` joins them: change orders, goodwill, rounds and late inputs from earlier baselines still count; fee at
  approval is the first baseline's, fee now the latest's; payments come from every baseline. A project whose newest
  version is a pending revision still shows its approved agreement. (`baseline_superseded` entries are still a planned
  kind on this base, so continuity comes from the versions themselves.)
- **Hero "₹ recovered"**: approved fee-increasing change-order value actually received (`recoveredOf`): payments (net of
  refunds, tax taken out at the scope's rate) go to the base fee first, then to change orders in approval order. Shown
  for the last 12 months, this month and all time, with the count of change orders paid for, per currency. "Show INR
  equivalent" uses the scope's locked FX rate when it locks INR (server) and `/api/fx` today's reference rate for the rest
  (named with its source and date). Not tied to invoices: money recorded or paid without an invoice counts too.
- **Money**: received, outstanding (tax-inclusive agreed total − received), overdue (issued invoices past due via
  `invoiceStatuses`; under MSMED terms the due date is the earlier of the invoice due and issue + agreed days, or the
  statutory 15), **MSMED interest estimate** (s.16: 3 × RBI Bank Rate, compounded monthly; `RBI_BANK_RATE_PCT` = 5.75 %,
  the Bank Rate from 7 Oct 2026 per RBI's MPC statement; override with `SCOPEFLOW_RBI_BANK_RATE_PCT`), TDS certificates
  pending (projects with TDS terms and money received; `tds_credit` is not an active entry kind yet, so all are pending).
- **Flow**: median change-order approval time (proposal → decision), radar catches (forwarded emails the radar read as
  out of scope, and how many were marked done) → change orders proposed → approved. Rate-card hit rate and retainer
  utilisation are shown as "—" with an explanation: they need WS-05's rate card and `usage` entries.
- **By month** table (last 12 months: change orders, recovered, goodwill), a new observation for recovered money.
- **Filters**: period (all / this month / last 12 months / this financial year, by first approval date), client and
  currency (`filterProjects`, `filterOptions`); **CSV export** `GET /api/insights?format=csv` (`insightsCsv`, formula-like
  text neutralised).

Tests: `tests/golden/ws-09-insights.test.mjs` + `ws-09-insights.golden.json` (fixture ledgers incl. a supersede, MSMED,
TDS, FX lock), `tests/ws-09-insights.mjs` (route: supersede keeps the v1 CO and payment — the old route returned 1 approved
CO; filters; CSV; 401), `tests/e2e/ws-09-insights.spec.ts` (hero ₹ recovered + all earlier cards, filters, CSV link).
All `@covers SF-16`. No migration.

Gaps: mode filter (modes are per account, WS-08 — nothing to filter by yet); rate-card hit rate and retainer
utilisation wait for WS-05 data; MSMED acceptance date is taken as the invoice issue date (no `delivery_accepted` entry yet).

## Part C

### L9 / LT-18 / SF-21: themes A/B, dark mode, switcher

Ported from `hark/redesign-etched` (5bd6c60), **tokens and themes only**. This base already carries that branch's
theme B ("ScopeFlow original") as the single `:root` palette, so the port adds what was missing:

- **Theme A "Etched"** (`:root[data-theme="a"]` in `app/globals.css`): cream type on grained cobalt, translucent cream
  rules, square 2 px corners, Etched grain and flat tick rule. Colour and shape tokens only.
- **Dark mode for both themes**: `:root[data-scheme="dark"]` (B dark: cream ink on night cobalt, light-cobalt accent) and
  `:root[data-theme="a"][data-scheme="dark"]` (Etched at night: deep cobalt). The few literal colours elsewhere in the
  sheet (placeholder, `.vc-slip`, `select option`) are re-pointed to tokens off theme B light.
- **Default unchanged**: theme B light is the untouched `:root` block, so the default renders exactly as before
  (Playwright runs light); goldens untouched.
- **State** (`lib/theme.ts`, pure, importable by the server layout): `<html data-theme="a|b" data-mode="light|dark|system"
  data-scheme="light|dark">`, set before first paint by `themeScript` (inline in `app/layout.tsx`, no flash) from
  `localStorage` (`scopeflow:theme`, `scopeflow:mode`). Mode `system` (the default) follows `prefers-color-scheme`, live.
  **Client pages** (`/review/…`) always use `system`, whatever the browser stored.
- **ThemeProvider + switcher** (`app/components/slots/theme-switcher.tsx`, default export `ThemeSwitcher`, named
  `ThemeProvider`, `useTheme`, `saveChoice`): four colour squares (`SWATCHES` in `lib/theme.ts`: Original light,
  Original dark, Etched light, Etched dark; `aria-pressed`, named by `aria-label`). Picking one stores that theme and an
  explicit light or dark mode; until then the mode stays `system` and the square for the current scheme is marked. In the header (`app/ui.tsx`; hidden in print). `ThemeProvider` (mounted once in the layout) loads the account's
  choice once signed in (`data-auth="in"`), so it follows the owner to any browser. Own hook on
  `useSyncExternalStore` rather than `next-themes`: next-themes handles one attribute, and this needs two axes plus the
  client-page rule.
- **Per account**: migration `db/migrations/0024_ws-09_theme.sql` adds `account_settings.theme_style` ('a'|'b') and
  `theme_mode` ('light'|'dark'|'system'), NULL = never chosen. Account deletion already removes the row.
  `GET /api/theme` → `{signedIn, theme, mode}` (200 `{signedIn:false}` when signed out, so public pages log no error);
  `PUT /api/theme {theme, mode}` (session only, same-origin, 30/min) → 400 with `fields` on anything else.

Tests: `tests/property/ws-09-theme.test.mjs` (`@covers L9 LT-18 SF-21`): every token text/background pair
(ink/ink-2/ink-3 on bg/surfaces, accent and on-accent, paper, status colours, band, shadcn tokens) ≥ 4.5:1 in
A light, A dark, B light, B dark (translucent tokens composited on `--bg`; lowest is 5.4:1); theme blocks set no fonts;
default `:root` keeps B light; preference parsing. `tests/e2e/ws-09-theme.spec.ts` (`@covers L9 LT-18 SF-21`): switch
A↔B and dark from the header, reload persists, a cleared browser gets the account's choice, system mode follows the
emulated scheme, 400 on bad input, client page follows `prefers-color-scheme` with a stored dark choice.
`tests/property/type-scale.test.mjs` unchanged and green.

Judgment calls / gaps:
- Etched's Garamond and its per-element font overrides were **not** ported: the strict type scale (two families,
  `type-scale.test.mjs`) wins; theme A uses Fraunces + Instrument Sans. The Etched art (`etched-horse.webp`,
  `etched-plain-*.webp`) and its theme-specific `Mark`/`Vignette` variants were not ported (unused on this base).
- "Client page respects the owner's brand accent": the review page follows the system scheme; applying the owner's
  brand accent on top of the dark tokens is not done here (brand colour belongs to the review page owner).
- `tests/property/ws-00-contracts.test.mjs` (WS-00's) now lets an implemented slot (`theme-switcher`) have a real body;
  other slots still must render null. Listed as a change request.
