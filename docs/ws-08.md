# WS-08: Workspace modes, onboarding, account, billing & compliance

Covers H10, M12, M13, M32, L13, LT-04, LT-11, LT-16, LT-17, LT-20, LT-22, SF-11, SF-12, SF-17, SF-25
(supporting M26b for WS-10). Migrations `0022_ws-08_modes_billing_tombstones.sql` and
`0022a_ws-08_account_functions.sql`.

## What changed

### Workspace modes (SF-17, plan §7)
* `account_settings.mode` (`freelancer` default, `agency`, `consumer`, `enterprise`) with a per-project
  override `projects.mode`. `lib/mode.ts`: `currentMode(owner, projectId?)`, `modeDefaults(mode)` (pure),
  `FEATURES`, `featuresFor(mode)`. The pure part lives in `lib/mode-core.ts` (client components import it; `lib/mode.ts` re-exports it and adds the database read).
* A mode sets defaults, ordering and wording only. Every mode lists every feature exactly once; the
  **All features** page (`/account/features`) links to all of them in every mode.
* Enterprise: retention policy required (30–3650 days; switching to Enterprise sets 180 when none is
  set; `PUT /api/settings` refuses "server default" with `code: retention_required`), audit export first,
  countersign roles on, one-time codes required for new projects (when codes can be delivered), strict
  contact lock flag (enforced by WS-02's contact lock), data-residency note.
* Agency/Consumer: one-time code on by default for new projects. Consumer: buyer-side wording
  ("brief", "vendor", "variation"), GST invoicing/MSMED/TDS off by default.
* API: `GET/PUT /api/workspace/mode` (`{mode, project_id?}`; `mode: null` clears a project override).

### Onboarding (LT-04, SF-11, LT-16, LT-17)
* New accounts that sign up without a `return_to` go to `/onboarding` (3 steps: mode; country,
  currency, time zone; business name, GSTIN, Udyam number/date/category, UPI VPA, payment terms).
  Defaults come from the browser locale (en-IN → India, INR, Asia/Kolkata). GST 18% is suggested only
  with a valid GSTIN; payment terms cite MSMED s.15 for Udyam micro/small units.
* `POST /api/profile/onboarding` saves it in one call; `GET /api/me` now returns `defaults`
  (mode, currency, time zone, country, onboarded, plan badge).
* `POST /api/scopes` without a currency uses the owner's default currency; new projects start in the
  account's time zone (`PUT /api/workspace/account {timezone, country}`).
* `TimezoneSelect` slot (`app/components/slots/timezone-select.tsx`): searchable combobox, common zones
  first ("Kolk"/"india" → Asia/Kolkata). Its CSS module lives in `app/components/timezone-select.module.css`
  (the slots folder holds one file per slot).
* GSTIN validation (`lib/gstin.ts`): format, mod-36 check character and state code (must match the
  registered state). Applied in onboarding and on the business profile whenever the profile is
  GST-registered or the tax ID is GSTIN-shaped (`400 code: invalid_gstin`). UPI VPA
  (`lib/vpa.ts`, `^[a-zA-Z0-9.\-_]{2,256}@[a-zA-Z]{2,64}$`) with a QR preview and `upi://pay` link.
* Business profile gains `upi_vpa`, `udyam_number`, `udyam_date`, `udyam_category` (read by WS-03's
  `loadMsmeProfile()` and WS-04). Invoice prefix rule matches WS-03's `invoicePrefixProblem()`:
  "Invoice numbers must be 16 characters or fewer".

### Plans and ScopeFlow's own billing (M12, M13, L13, SF-12)
* `accounts_plans` (one row per owner). `limitsFor(owner)` resolves the account's entitlement:
  no row → server default (`SCOPEFLOW_PLAN`, default `beta`); active → plan (7 days past the paid period
  tolerated); halted (payment failed) → plan for a 7-day grace, then Free; cancelled → plan to period
  end; expired → Free. `lib/plans.ts`: Free (1 active project), Pro ₹499/month or ₹4,499/year,
  Agency ₹1,499/month (3 seats); Solo kept only as a test arm.
* Project cap counts `archived IS NULL AND owner_deleted IS NULL` (M12); the message matches the Plans
  page copy "1 active project (archived ones don’t count)". The Plans page renders from the same table.
* Checkout `POST /api/billing/checkout` (browser sessions only): INR → Razorpay Subscriptions, other
  currencies → Stripe Billing. Webhooks: `/api/billing/razorpay/webhook`
  (`subscription.activated/charged/halted/cancelled/...`) and `/api/billing/stripe/webhook`; each event
  is applied once (`billing_events`). Every payment gets ScopeFlow's own GST invoice
  (`billing_invoices`, `SF-YYYY-NNNNN`, `/plans/invoices/<id>`).
* **Local double**: on a localhost `APP_URL`, outside Render, with no billing keys, checkout goes to
  `/plans/checkout` and `POST /api/billing/local/pay` replays Razorpay-shaped events through the real
  handler (no money moves). CI uses it.

### Account deletion keeps the client's record (H10, LT-22)
* `DELETE /api/account` cancels the subscription, then one SECURITY DEFINER call
  `scopeflow.ws08_close_account(owner, now, retain_until)`:
  * deletes the owner's own data: profile, settings, templates, drafts, API/OAuth tokens, rate limits,
    plan row, audit events, unsent/undecided versions, forwarded emails, and every project without a
    client decision, ledger entry, invoice or confirmed payment; plus, when those tables exist,
    WS-03 `msme_profiles`, WS-04 `payment_accounts`/`payment_oauth_states`, WS-05 `rate_cards`,
    WS-06 `owner_contacts`/`mail_outbox`/`wa_*`/`capture_drafts`, WS-10 analytics rows;
  * tombstones the rest (`projects.owner_deleted`, `retain_until` = now + 8 years, the GST record
    period, `SCOPEFLOW_TOMBSTONE_RETENTION_YEARS` to change; CA to confirm). Tombstoned projects are
    read-only (triggers refuse new versions, decisions, ledger entries, cosigns, payments, invoices and
    project edits; retention redaction still works). Decided versions, ledger, invoices (and WS-03 credit
    notes/receipt vouchers/TDS credits), receipts and payments stay readable through the client's link;
  * refuses under legal hold (409 `legal_hold`), as before.
* Then the Neon Auth login is deleted through the SDK's `deleteUser`. When the sign-in service refuses
  (the Better Auth delete-user endpoint is disabled by default), the reply and the Account page say
  the login stays (`login_deleted: false`).
* Client links: `GET /api/account/notice/<token>` returns the closed-account banner text ("The creator
  closed their ScopeFlow account; this record is kept for you until <date>") and the data notice.
  `<AccountClosedBanner token/>` (`app/components/account-closed-banner.tsx`) is ready for WS-07.
* The daily job (`scripts/redact-expired.mjs`) purges tombstones after `retain_until` via
  `scopeflow.ws08_purge_tombstone(project, now)`, never under legal hold.

### Retention (M32, M26b)
* Default client IP/browser retention is **180 days** (founder decision): the server default when
  `SCOPEFLOW_CONTEXT_RETENTION_DAYS` is unset; migration 0022 sets 180 on existing settings rows
  without a value. `SCOPEFLOW_CONTEXT_RETENTION_DAYS=keep` restores "keep until the project is deleted".
* `GET /api/scopes` no longer redacts (M26b): redaction runs in the daily job and when the owner saves a
  new period.
* Draft deletion (button and expiry) runs in `scopeflow.ws08_delete_draft(project, owner)`.
  WS-08 no longer sets `scopeflow.allow_delete` from the app; with WS-10's 0016 the bypass works only
  inside these functions, so production can switch to the `scopeflow_app` login role (C7). 0022a grants
  EXECUTE on the three functions to `scopeflow_app` when that role exists.

### Audit export (SF-25)
* `GET /api/audit/export?from&to&format=jsonl|csv`, account admin in a browser session only
  (`403 admin_only` for tokens). Records: export header, projects (head hash, retention, legal hold,
  closed-account state), decisions (each with its `/api/verify` link), ledger entries, countersignatures,
  contact changes (WS-02's `contact_history` when present), review-link opens and admin events
  (`audit_events`: mode, retention, plan, onboarding, export). The last JSONL line seals the file
  (SHA-256 of the lines before it, signed with the record key); the response carries
  `X-Scopeflow-Sha256` and `X-Scopeflow-Signature`.

### Accessibility and navigation (LT-11, LT-20, LT-13 account copy)
* Sign-up/sign-in labels name only their field; hints are separate elements tied by `aria-describedby`.
* `/account` uses plain links (no history rewriting), so Back leaves it.
* Account page: mode, time zone, UPI QR preview, Udyam, Payments (`<PaymentSettings/>` slot),
  legal hold explainer, audit export, analytics opt-out (shown only when WS-10's `/api/analytics`
  answers) and honest deletion copy.

## New environment variables (all optional)
| Variable | Purpose |
|---|---|
| `SCOPEFLOW_CONTEXT_RETENTION_DAYS` | Server default retention (1–3650); default now 180; `keep` disables |
| `SCOPEFLOW_TOMBSTONE_RETENTION_YEARS` | How long a closed account's client records are kept (1–20, default 8) |
| `RAZORPAY_BILLING_KEY_ID`, `RAZORPAY_BILLING_KEY_SECRET`, `RAZORPAY_BILLING_WEBHOOK_SECRET` | ScopeFlow's own Razorpay account for subscriptions |
| `RAZORPAY_BILLING_PLAN_{PRO,AGENCY}_{MONTH,YEAR}` | Razorpay plan ids |
| `RAZORPAY_BILLING_API_URL` | Override (tests) |
| `STRIPE_BILLING_SECRET_KEY`, `STRIPE_BILLING_WEBHOOK_SECRET`, `STRIPE_BILLING_PRICE_{PRO,AGENCY}_{MONTH,YEAR}`, `STRIPE_BILLING_API_URL` | Stripe Billing for non-INR |
| `SCOPEFLOW_BILLING_SELLER_NAME`, `SCOPEFLOW_BILLING_SELLER_ADDRESS`, `SCOPEFLOW_BILLING_SELLER_GSTIN`, `SCOPEFLOW_BILLING_SAC` (default 998315), `SCOPEFLOW_BILLING_LUT_ARN` | ScopeFlow's own seller details on its subscription invoices |

## Operator steps
1. Run migrations (0022, 0022a). Existing accounts without a retention period get 180 days.
2. To sell plans: create the Razorpay plans (and/or Stripe prices), set the variables above and point the
   webhooks at `/api/billing/razorpay/webhook` and `/api/billing/stripe/webhook`.
3. To actually delete logins on account deletion, enable Neon Auth's delete-user endpoint; otherwise
   users are told their login remains.
4. Schedule `node scripts/redact-expired.mjs` daily (redaction, draft expiry, tombstone purge).
5. After WS-10 merges: switch production `DATABASE_URL` to the `scopeflow_app` role.
